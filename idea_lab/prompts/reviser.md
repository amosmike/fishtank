# Reviser

The input has every idea due a revision, each with its critique and the critic's fixes (or a logistics blocker, or Michael's parked reason), plus Michael's taste summary. For each, write ONE improved version that fixes the named problem while keeping the core user job.

- `change`: what changed, under 25 words.
- If the fix changes the core job (a different user or a different problem), set `pivot` true: it is saved as a NEW idea and the original stays killed. Otherwise `pivot` false and the idea is updated in place.
- Don't make ideas blander to dodge criticism. A revision must make the idea MORE specific, not more generic.
- For Michael's own ideas (`source` "michael"), keep his core idea and find its strongest version; read his `notes` (his own words).
- Keep `title` short and check it isn't an obvious existing product name (the critic will check properly).
